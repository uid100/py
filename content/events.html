From Step-by-Step Programs to Event-Driven Programs

So far in this course, you have written programs that follow a clear, predictable flow: instructions run in sequence, decisions are made with conditionals, and repetition is handled with loops. You then learned how to organize programs using functions, modules, and object-oriented programming (OOP).

This approach is known as sequential programming. It works very well for many types of problems, especially when the program has a clear start, middle, and end. However, many real-world applications—especially those with graphical user interfaces (GUIs)— do not run from top to bottom in a straight line.

To build interactive applications, we need a different way of thinking about program flow: event-driven programming.

What Is Event-Driven Programming?

Event-driven programming is a programming paradigm where the flow of the program is determined by events rather than a fixed sequence of instructions.

An event is something that happens while a program is running, such as:

  • A user clicking a button
  • A key being pressed on the keyboard
  • The mouse moving over a window
  • A timer reaching a certain time

In an event-driven program, the application spends most of its time waiting for events to occur. When an event happens, the program responds by running specific code designed to handle that event.

Events, Triggers, and Event Handlers

Two key concepts in event-driven programming are triggers and event handlers.

A trigger is the condition or action that causes an event to occur. For example:

  • Clicking a button triggers a “button click” event
  • Pressing the Enter key triggers a “key press” event
  • Closing a window triggers a “window close” event

An event handler is a function or method that runs in response to a specific event. You can think of an event handler as a specialized function whose job is to respond to exactly one type of event.

This concept should feel familiar: event handlers are usually written as functions or methods, and in object-oriented programs they are often methods of a class.

The Event Loop

Event-driven programs rely on an event loop. The event loop is a part of the framework or library (not your code) that:

  • Waits for events to occur
  • Detects when an event has happened
  • Calls the correct event handler

Instead of writing a while True loop yourself, the event loop runs continuously behind the scenes. Your job as a programmer is to define what should happen when certain events occur.

This is why event-driven programs may seem unusual at first: the program does not explicitly control the order in which things happen. The user’s actions do.

Graphical User Interfaces (GUIs)

A graphical user interface (GUI) allows users to interact with a program using visual elements such as windows, buttons, labels, text boxes, sliders, and charts.

GUIs are a natural fit for event-driven programming because nearly everything a user does in a GUI generates events. Each button click, mouse movement, or key press is an event that can trigger code to run.

In a GUI-based program:

  • The program creates and displays interface elements
  • Event handlers are connected to those elements
  • The event loop waits for user interaction

Event-Driven Programming in Python

Python supports event-driven programming through a variety of libraries and frameworks. In this course, you will be introduced to two important tools:

  • tkinter – Python’s standard library for building graphical user interfaces with buttons, windows, and other widgets
  • matplotlib widgets – interactive controls (such as sliders and buttons) used with graphs and visualizations

Both libraries use event-driven design. You will write functions that respond to user actions, and the framework will handle the event loop for you.

Key Takeaways

  • Event-driven programming responds to events rather than running strictly top-to-bottom
  • Events are triggered by user actions or system conditions
  • Event handlers are functions or methods that run when an event occurs
  • GUIs rely heavily on event-driven programming
  • Python libraries like tkinter and matplotlib widgets make event-driven programming accessible
